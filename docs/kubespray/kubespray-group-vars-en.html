Kubespray group_vars — Complete Educational Guide

A module-by-module walkthrough of every file under inventory/sample/group_vars: what it controls, key variables, defaults, and when to change them for production Kubernetes clusters.

KubesprayAnsible group_varsEducationalEN

1. Introduction

Kubespray is an Ansible-based toolkit for deploying production-ready Kubernetes clusters. Almost every behavioral switch lives in Ansible variables. The primary place you customize those variables is inventory/<cluster>/group_vars/.

This guide walks through every sample group_vars file shipped by upstream Kubespray (inventory/sample/group_vars), explaining purpose, important modules/variables, defaults, and when to change them.

Learning goal: After this document you should be able to open any file under group_vars, know which hosts it affects, and tune the right knobs for networking, runtime, cloud, offline installs, and add-ons.

2. Inventory Architecture

Kubespray inventory groups:

GroupRoleNotes
kube_control_planeAPI server, scheduler, controller-managerCan also be in kube_node if schedulable
kube_nodeWorker nodes (run pods)May overlap with control plane
etcdetcd membersOdd number (3/5) recommended
calico_rrCalico route reflectorsAdvanced BGP designs
bastionSSH jump hostWhen nodes are unreachable directly
k8s_clusterDynamic unionkube_node ∪ kube_control_plane ∪ calico_rr
Key rule: Variables under group_vars/all/ apply to every inventory host (including standalone etcd). Variables under group_vars/k8s_cluster/ apply to Kubernetes nodes only — not to etcd hosts that sit outside k8s_cluster.

3. Variable Precedence

Kubespray expects customization mainly via inventory group_vars. Precedence (simplified, high wins):

  1. Extra vars (ansible-playbook -e / -e @file.yml) — always win
  2. Inventory host_vars
  3. Inventory group_vars (most common place to edit)
  4. Role defaults inside Kubespray roles
Caution: Overriding internal role vars with -e can break unexpectedly across upgrades. Prefer documented inventory variables.

all all.yml — Global Cluster Settings

group_vars/all/all.yml

Applies to every host. Covers binary paths, API load balancing, DNS, proxies, certificates, NTP, and cloud-provider selection.

4.4 Cloud provider

After Kubernetes v1.31, in-tree providers are gone. Set:

cloud_provider: external
external_cloud_provider: openstack   # or vsphere, oci, huaweicloud, hcloud, manual

Then fill the matching cloud YAML under group_vars/all/. Use manual if you install CCM yourself.

all offline.yml — Air-Gapped Installs

Either override entire domains (github_url, dl_k8s_io_url, …) or single artifacts:

  • kubeadm_download_url, kubectl_download_url, kubelet_download_url
  • cni_download_url, crictl_download_url, etcd_download_url
  • CNI tools: calicoctl_download_url, ciliumcli_download_url
  • Runtimes: containerd_download_url, runc_download_url, crio_download_url, nerdctl_download_url

azure.yml

Requires Azure AD + network identifiers: azure_tenant_id, azure_subscription_id, azure_aad_client_id/secret, azure_resource_group, VNet/subnet/NSG/route table names. Separate azure_csi_* for Disk CSI; set azure_csi_enabled: true.

gcp.yml

gcp_pd_csi_enabled + path to service-account JSON (gcp_pd_csi_sa_cred_file).

openstack.yml

  • Legacy/in-tree LBaaS knobs: openstack_lbaas_*
  • External CCM: external_openstack_lbaas_*, network lists, app credentials
  • Cinder CSI: cinder_csi_enabled, image tags, storage_classes

vsphere.yml

external_vsphere_vcenter_*, user/password (or env), datacenter, cluster id; vsphere_csi_enabled.

oci.yml

Oracle CCM auth (tenancy, user, key, fingerprint or instance principals), VCN/subnets, rate limits, security list management.

hcloud.yml

Hetzner: API token, networks support, LB location/zone, private ingress options.

huaweicloud.yml

Auth URL / access keys (often from env), LBaaS subnet/network, controller image repo/tag.

upcloud.yml

upcloud_csi_enabled + credentials via UPCLOUD_USERNAME/UPCLOUD_PASSWORD; optional storage classes (maxiops/hdd).

CP kube_control_plane.yml

group_vars/kube_control_plane.yml

Overrides resource reservations only for control-plane hosts (higher than workers typically):

  • kube_memory_reserved, kube_cpu_reserved, kube_ephemeral_storage_reserved, kube_pid_reserved
  • system_memory_reserved, system_cpu_reserved, …

Protects API server / etcd (if colocated) from pod pressure.

5. Recommended Configuration Workflow

  1. Copy inventory/sample → inventory/mycluster
  2. Edit inventory hosts & groups
  3. In all/all.yml: proxies, NTP, external LB / VIP, cloud_provider
  4. In k8s-cluster.yml: CIDRs, CNI choice, container_manager, DNS
  5. Tune matching k8s-net-*.yml
  6. Enable add-ons in addons.yml
  7. If air-gapped, fill offline.yml
  8. If cloud, fill the cloud YAML + CSI flags
  9. Run ansible-playbook -i inventory/mycluster/hosts.yaml cluster.yml
# Minimal on-prem example snippets
# k8s-cluster.yml
kube_network_plugin: calico
container_manager: containerd
kube_pods_subnet: 10.244.0.0/16
kube_service_addresses: 10.96.0.0/12

# addons.yml
metrics_server_enabled: true
metallb_enabled: true
