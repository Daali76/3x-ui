راهنمای کامل آموزشی group_vars در Kubespray

مرور ماژول‌به‌ماژول تمام فایل‌های inventory/sample/group_vars: کنترل چه چیزی، متغیرهای کلیدی، پیش‌فرض‌ها، و زمان تغییر برای کلاسترهای production.

KubesprayAnsible group_varsآموزشیFA

۱. مقدمه

Kubespray ابزاری مبتنی بر Ansible برای نصب Kubernetes سطح production است. تقریباً تمام رفتار کلاستر با متغیرهای Ansible کنترل می‌شود و محل اصلی تنظیم آن‌ها inventory/<cluster>/group_vars/ است.

این راهنما تمام فایل‌های نمونه group_vars رسمی Kubespray (inventory/sample/group_vars) را بخش‌به‌بخش توضیح می‌دهد: هدف هر فایل، متغیرهای مهم، مقدار پیش‌فرض، و زمان تغییر آن‌ها.

هدف یادگیری: بعد از این سند باید بتوانید هر فایل زیر group_vars را باز کنید، بفهمید روی کدام hostها اثر دارد، و تنظیمات شبکه، runtime، cloud، نصب آفلاین و add-on را درست انتخاب کنید.

۲. معماری Inventory

گروه‌های اصلی inventory در Kubespray:

گروهنقشتوضیح
kube_control_planeAPI server، scheduler، controller-managerاگر schedulable باشد در kube_node هم می‌آید
kube_nodeWorkerها (اجرای Pod)می‌تواند با control plane هم‌پوشانی داشته باشد
etcdاعضای etcdتعداد فرد (۳ یا ۵) توصیه می‌شود
calico_rrRoute Reflectorهای Calicoسناریوهای پیشرفته BGP
bastionJump host برای SSHوقتی نودها مستقیم در دسترس نیستند
k8s_clusterاتحاد پویاkube_node ∪ kube_control_plane ∪ calico_rr
قانون کلیدی: متغیرهای group_vars/all/ روی همه hostهای inventory اعمال می‌شوند (حتی etcd جدا). متغیرهای group_vars/k8s_cluster/ فقط روی نودهای Kubernetes اثر دارند — نه روی etcdهایی که خارج از k8s_cluster هستند.

۳. اولویت متغیرها (Precedence)

Kubespray عمدتاً از inventory group_vars برای سفارشی‌سازی استفاده می‌کند. اولویت ساده‌شده (بالاتر برنده است):

  1. Extra vars (ansible-playbook -e / -e @file.yml)
  2. Inventory host_vars
  3. Inventory group_vars (رایج‌ترین محل ویرایش)
  4. پیش‌فرض‌های داخل roleهای Kubespray
هشدار: Override کردن متغیرهای داخلی role با -e ممکن است در آپگرید بشکند. ترجیحاً فقط متغیرهای مستند inventory را تغییر دهید.

۴.۴ Cloud Provider

از Kubernetes v1.31 به بعد فقط external CCM:

سپس فایل YAML ابری متناظر را پر کنید. مقدار manual یعنی CCM را خودتان نصب می‌کنید.

CP kube_control_plane.yml

group_vars/kube_control_plane.yml

فقط روی hostهای control plane، رزرو منابع را override می‌کند (معمولاً بیشتر از worker):

  • kube_memory_reserved، kube_cpu_reserved، kube_ephemeral_storage_reserved، kube_pid_reserved
  • system_memory_reserved، system_cpu_reserved، …

API server (و etcd در صورت colocated) را در برابر فشار Pod محافظت می‌کند.

۵. روند پیشنهادی پیکربندی

  1. کپی inventory/sample → inventory/mycluster
  2. ویرایش hostها و گروه‌ها
  3. در all/all.yml: پروکسی، NTP، LB/VIP، cloud_provider
  4. در k8s-cluster.yml: CIDRها، انتخاب CNI، container_manager، DNS
  5. تنظیم k8s-net-*.yml متناظر
  6. فعال‌سازی add-onها در addons.yml
  7. اگر آفلاین هستید: offline.yml
  8. اگر cloud هستید: فایل ابری + فلگ CSI
  9. اجرا: ansible-playbook -i inventory/mycluster/hosts.yaml cluster.yml
# نمونه حداقلی on-prem
# k8s-cluster.yml
kube_network_plugin: calico
container_manager: containerd
kube_pods_subnet: 10.244.0.0/16
kube_service_addresses: 10.96.0.0/12

# addons.yml
metrics_server_enabled: true
metallb_enabled: true
